# shit

magic undo for the command line

You ran a command and want its effects undone: an edit, a botched `mv`, an `rm` that took more than you meant. `shit` watches kernel surfaces, captures pre-images with your filesystem's copy-on-write where it has one, and produces an undo plan you approve.

## Status

Pre-1.0. APIs, wire formats, and on-disk layouts are unstable. "Arbitrary command undo" holds only for the classes pinned by a green CI smoke today. See [Coverage today](#coverage-today) and [What doesn't work yet](#what-doesnt-work-yet).

Linux and FreeBSD run their smoke suites in CI. On macOS, CI runs the DYLD-interposer and wrapper smokes on hosted runners. The EndpointSecurity smokes run on a self-hosted Apple Silicon host inside a SIP-disabled Tart guest (see [macOS](#macos)). Windows is not supported.

## Install

There are no releases or packages yet. The Homebrew and AUR packaging directories are empty, so the only install path is building from source (below) and applying capabilities to the helper by hand. Packaging is tracked in #192.

Planned: a Homebrew tap, AUR, FreeBSD ports, and a signed `curl | sh`. No dates.

## How it works

`shit` is three binaries plus shell glue:

- **`shit`** — the CLI: `shit undo`, `shit redo`, `shit list`, `shit show`, `shit pin`, `shit doctor`, …
- **`shitd`** — a per-user daemon that owns the snapshot store, the sqlite index, the IPC sockets, and the undo planner.
- **`shit-helper`** — a privileged helper that drives kernel-level capture: EndpointSecurity on macOS, fanotify-perm + eBPF-LSM on Linux, kqueue + LD_PRELOAD shim on FreeBSD (the shim is the supported default; running without it is reported by `shit doctor` as the degraded `kqueue-only` tier). On un-entitled macOS installs, FSEvents supplies watch readiness and post-hoc diagnostics only; actionable capture there comes from the DYLD interposer.
- **shell hooks** (bash, zsh, fish) that bracket each command with metadata events sent over a per-user Unix-domain-socket.

When a command writes, renames, unlinks, or otherwise mutates a file inside a tracked process subtree, the helper captures the pre-image *before* the kernel allows the syscall to complete. Depending on the active tier and filesystem, it uses `clonefile` (APFS), `reflink` (btrfs/XFS), hardlink, or bounded streaming copy. A `zfs clone` engine exists in `shit-capture` but the helper does not call it (see [FreeBSD](#freebsd)). Blobs land in a content-addressed store (blake3 + zstd) under `$XDG_STATE_HOME/shit/`. When you run `shit undo`, the daemon's planner walks the captured events, computes an inverse-op DAG, shows you exactly what it'll do, and applies it on your `y`.

Honesty principle: any command class we cannot mechanically reverse goes in the [refuse-list catalog](#refuse-list-what-we-explicitly-wont-undo) — `shit undo` exits non-zero with a one-line reason rather than silently producing a partial undo.

## Coverage today

A class counts as covered only if a non-excluded smoke for it is wired into a CI job. Most jobs run on hosted runners. The Linux smokes that need the eBPF-LSM tier (and two tier-agnostic ones) run on a self-hosted LSM runner, and that job is skipped with a warning when the runner is offline, so those rows are evidence only for runs where it was online. The tables below are generated from the `# SMOKE_*` and `# EXCLUDED_BY` headers of `tests/smoke/*.sh` by `tools/audit/readme-coverage.py`, and CI fails when they drift. They list smoke names grouped by surface family and by where they run, taken from the workflow job that names each smoke; they do not repeat what each smoke asserts. Read the smoke for that. A smoke that exists but carries `EXCLUDED_BY` is listed separately and is not evidence.

Capture mechanisms, named by the kernel surface that fires:

- "LSM" is the helper's eBPF program attached to `bpf_lsm_<hook>` (Linux, needs `lsm=bpf` and `cap_bpf,cap_perfmon,cap_sys_admin` on the helper). Smokes with `SMOKE_TIER_REQUIRED: lsm` need it.
- "shim" is the LD_PRELOAD shim in `crates/shit-preload-shim/` (DYLD interposer on macOS). It is injected for install-pattern commands by `crates/shit/src/auto_inject.rs`.
- "wrapper" is a packaging wrapper script in `packaging/` that brackets the real binary with `shit-helper <tool>-event` (package managers, containers, cloud tools, services, firewalls).
- Shell-state restore (`cd`, `set -e`, `alias`) uses the DEBUG-trap snapshot in `crates/shit-shell/src/state.rs`.

Smokes marked platform "any" branch on the runtime OS inside the script, but each runs only where a workflow job names it. The "Any OS" tables show where.

### Known limits

Some items below are limits of pinned classes; the ones marked unpinned have no smoke at all.

- macOS: SIP-protected binaries (`/bin/rm`, `/bin/mv`, `/bin/cp` and the like) drop `DYLD_INSERT_LIBRARIES` on exec, so the default (non-EndpointSecurity) tier does not capture them. Under EndpointSecurity, `es-bin-rm-undo-macos` and `es-bin-mv-undo-macos` pin undo of `/bin/rm` and `/bin/mv`. Undo of `/bin/rm -r` on a tree (#280) and of `mv` over an existing file (#279) does not work yet.
- Static binaries and binaries that issue raw syscalls (Go programs, for example) bypass the DYLD interposer on macOS and the LD_PRELOAD shim on FreeBSD. No smoke pins this either.
- macOS `pip install --user --force-reinstall` reaches full restore on trunk, but `pip-install-user-undo-macos` does not yet gate on that outcome. It passes; it is not a gate.
- Linux `pip install --user --force-reinstall` accepts two outcomes in its smoke: full restore through recursive pre-image, or a graceful fallback.
- Strict capture (`SHIT_STRICT_CAPTURE`, opt-in) refuses an undo when capture was provably incomplete for the touched paths. It is off by default. The `strict-*` smokes run on Linux and FreeBSD only. On FreeBSD, strict mode compares file birth times with the wall clock at the start of the command, so a realtime clock step while a command runs can misclassify which files the command created.
- `kubectl delete` restore is context-drift gated. `terraform apply` reverses through `terraform destroy`; `terraform destroy` reverses through state-push plus `terraform apply`.
- `kill`, `pkill` and `killall` produce an informational note and a restart hint. Processes are not reanimated.
- apt rollback delegates to `apt-get history-rollback` on apt 3.2 and later. Older apt synthesizes an inverse invocation (`refuse-without-native-delegate`).
- The FreeBSD smokes run on UFS and ZFS legs. A per-event ZFS clone engine exists in `crates/shit-capture/src/cow/` and is validated in isolation by `zfs-clone-primitives-fbsd` and `zfs-clone-engine-fbsd`. Nothing in `shit-helper` or `shitd` calls it, so the ZFS smokes are engine tests, not evidence of a production ZFS tier.
- FreeBSD capture is kqueue plus the shim. The shim is the supported default; without it `shit doctor` reports the `kqueue-only` tier and prints a WARN block listing the pre-image classes you lose. The Capsicum sandbox is on by default; `SHIT_CAPSICUM=0` opts out.

### macOS capture paths

Two capture paths exist. EndpointSecurity needs a signed, entitled helper. The default path is the DYLD interposer, with FSEvents for readiness and diagnostics. `shit doctor` reports the active tier.

The EndpointSecurity smokes run in `macos-es.yml` on a self-hosted runner labelled `macos-es`. The runner drives a SIP-disabled Tart guest, and each smoke runs there as root against an ad-hoc signed helper. The workflow runs on `workflow_dispatch` and on trunk pushes, never on pull requests, so fork code never reaches the host. `es-rename-undo-macos` (#279) and `mkdir-out-of-watch-undo-macos` stay excluded. Everything else in the macOS table runs on hosted `macos-15` without ES.

## Refuse-list: what we explicitly won't undo

The planner short-circuits these classes at plan-build time with a one-line reason + optional remediation, surfaced under a `Refused (out of scope for shit undo):` block in `shit undo` output and exposed as `arbitrary_undo_coverage.refused_classes` in `shit doctor --json`. The list is in `crates/shit-planner/src/refuse.rs`.

| Class | Examples | Why |
|---|---|---|
| **remote-push** | `git push`, `docker push`, `podman push`, `npm publish`, `cargo publish`, `gh release upload` | remote replication is outside our capture-tier visibility |
| **history-rewrite** | `git rebase -i`, `git filter-branch`, `git filter-repo` | rewrites ref topology in ways the event journal cannot mechanically reverse; use `git reflog` |
| **identity-generation** | `gpg --gen-key`, `gpg --full-gen-key`, `ssh-keygen` | key material may already be distributed; deleting the file cannot un-publish a public key |
| **power-state** | `shutdown`, `reboot`, `halt`, `poweroff` | no inverse operation exists |
| **sandbox-escape** | `chroot`, `unshare`, `nsenter` | namespace / chroot transitions move execution into a context our capture tier no longer observes |
| **opaque-shell-mutation** | `source script.sh`, `. script.sh` | sourcing mutates the parent shell in arbitrary ways we don't introspect |
| **system-identity** | `useradd`, `userdel`, `usermod`, `groupadd`, `groupdel`, `passwd` | PAM + shadow-file mutations touch state we won't trust ourselves to roll back without per-OS policy |
| **cluster-release** | `helm install`, `helm upgrade`, `helm uninstall`, `helm delete`, `helm rollback` (also behind `sudo` or global flags such as `-n prod`); `helm list`, `status`, `get`, `template` and `show` are not refused | release state lives in the cluster and is not captured; undo would report success and change nothing |
| **firewalld** | `firewall-cmd` options that change state (`--add-*`, `--remove-*`, `--reload`, ...); `--state`, `--list-*` and `--get-*` are not refused | runtime and permanent zone state is not captured; undo would report success and change nothing |

## What doesn't work yet

Gaps where coverage is plausible but not shipped, or shipped without CI evidence.

### All platforms

- No install path. There is no tagged release and no package. Tracked in #192.
- Strict capture is opt-in. The default mode still produces an undo plan when capture was incomplete. Making refusal the default is undecided.
- Windows is not supported. [docs/windows-exploration.md](docs/windows-exploration.md) is a feasibility study (WSL 2 first, native behind a minifilter proof). There is no code.
- No `power-state` refuse-list smoke. The other six refuse classes have one.

### Linux

- Packaging install hooks. `apt install shit` to a `doctor`-green state is not built. The daemon and helper are built and given capabilities by hand.
- `docker pull` digest journaling and multi-target `docker rmi` are pinned by `docker-pull-digest-journaling-linux` and `docker-rmi-multi-target-undo-linux`. Other pull and rmi shapes are unpinned.

### FreeBSD

- NetBSD, OpenBSD and DragonFly are post-v1 stretch goals. The helper compiles only on FreeBSD.
- Raw-syscall and static binaries bypass the shim, and no smoke pins that.
- Containers and cloud tools are untested.

### macOS

- EndpointSecurity CI evidence comes from one self-hosted runner. When it is offline, nothing gates the ES path.
- SIP-protected system binaries are not captured by the default tier, only under EndpointSecurity. Raw-syscall binaries bypass the interposer, and no smoke pins that.
- Notarized helper distribution is not built. The entitled-ES path needs a self-built helper with a developer-signed entitlement. The daemon refuses helpers whose code signature does not validate. A signed and notarized release pipeline is the remaining work.
- DYLD interposer auto-install is not built. `shit dyld-hooks install` writes the shim to `/usr/local/lib/libshit_preload_shim.dylib` by hand; no package manager does it on first run.
- Containers, cloud tools and shell hooks are untested.

## Compatibility expectations

These should work in practice once the underlying mechanism is wired (no architectural blocker discovered), but they don't have a pinned smoke today:

- **`helm install / uninstall`** and **`firewall-cmd`** are refused (classes `cluster-release` and `firewalld`), pinned by `refuse-helm-linux` and `refuse-firewall-cmd-linux`. Before the refusal, `shit undo` exited 0 having applied nothing.
- **`ufw allow`** through the ufw wrapper is undone when ufw is enabled: `ufw-allow-undo-linux` checks that the rule is gone after undo.
- **`npm install -g`** over an older version restores the old module (`npm-install-global-undo-linux`), but undo exits 1 with a phantom conflict and leaves npm's temp symlink in `bin/` (#261).
- **`gem install`** over an older version restores every file (`gem-install-undo-linux`) and leaves the new gem's empty directory behind (#260).

† `file_release` is the in-place-write capture hook; on Linux ≥ 7.0 the LSM chain entry takes an extra `mnt_idmap` arg and the helper picks the right v1/v2 entry-point at load time via a BTF probe. Older kernels (< 7.0) use the legacy single-arg signature. A verifier-rejected attach on either fork degrades the helper to the fanotify-perm fallback rather than crashing.

## Windows

Windows is not a supported target. A native port is a bounded exploration, not a roadmap commitment: [docs/windows-exploration.md](docs/windows-exploration.md) surveys the options (WSL 2 first, native behind a minifilter proof of concept). No Windows code exists.

## Coverage matrix in JSON

`shit doctor --json` (schema_version 2) emits `arbitrary_undo_coverage` with three class lists, their counts, and validation metadata you can pin a CI gate to. There is no coverage percentage; a percentage over an undefined denominator misleads.

```json
"arbitrary_undo_coverage": {
  "covered_classes": ["container-compose", "container-network", "container-rm", "container-rmi", "container-volume", "fs-content-restore", "fs-device-node", "fs-metadata", "fs-post-hash-drift-detection", "fs-rename", "fs-tree", "kubectl-delete", "package-apt", "package-brew", "package-dnf", "preload-install", "process-note", "redirect-truncate", "service-systemctl", "shell-state", "tool-gh", "tool-network", "tool-terraform"],

  "pending_classes": ["bsd-shim-default", "linux-cap-install-verify"],
  "covered_count": 23,
  "refused_count": 9,
  "pending_count": 2,
  "last_validated_at": "",
  "snapshot_workflow_run_url": "",
  "binary_built_at": "2026-11-06T05:27:44Z"
```
